# Technical Writing Prompts

## API Documentation
```
Write comprehensive API documentation for:

API Name: [NAME]
Endpoint: [ENDPOINT]
Method: [GET/POST/PUT/DELETE/etc.]
Purpose: [DESCRIPTION]

Include:
- Endpoint description
- Request parameters (with types, required/optional)
- Request body schema (if applicable)
- Response codes and meanings
- Response body schema
- Example requests
- Example responses
- Error scenarios
- Authentication requirements
- Rate limiting info
```

## User Guide
```
Create a user guide for:

Product/Feature: [NAME]
Target Users: [USER LEVEL]
Key Functionality: [DESCRIBE]

Structure:
1. Introduction/Overview
2. Getting Started
3. Step-by-step instructions with screenshots
4. Common use cases
5. Tips and best practices
6. Troubleshooting
7. FAQ
```

## README Template
```
Create a comprehensive README for a project:

Project Name: [NAME]
Description: [BRIEF DESCRIPTION]
Technology Stack: [TECHNOLOGIES]
Key Features: [LIST FEATURES]

Include:
- Project title and description
- Badges (build status, coverage, etc.)
- Table of contents
- Installation instructions
- Usage examples
- Configuration options
- API reference (if applicable)
- Contributing guidelines
- License information
- Contact/support info
```

```
Write a technical specification document:

Feature/System: [NAME]
```

## Release Notes
```
Create release notes for version [VERSION]:

Project: [NAME]
Release Date: [DATE]
Changes: [LIST CHANGES/COMMITS]

Format:
- Version number and date
- Overview of release
- New Features (with descriptions)
- Improvements/Enhancements
- Bug Fixes
- Breaking Changes (if any)
- Deprecations
- Known Issues
- Upgrade Instructions
```

## Change Log
```
Maintain a detailed change log:

Project: [NAME]
Version: [VERSION]
Type of Changes: [FEATURES/FIXES/BREAKING/etc.]

Follow keep a changelog format:
- [VERSION] - YYYY-MM-DD
  - Added: New features
  - Changed: Changes to existing functionality
  - Deprecated: Soon-to-be removed features
  - Removed: Removed features
  - Fixed: Bug fixes
  - Security: Security fixes
```

## Database Schema Documentation
```
Document database schema for:

Database: [NAME]
Type: [SQL/NoSQL/etc.]

For each table/collection:
- Name and purpose
- Columns/fields with data types
- Constraints (primary key, foreign keys, unique, not null)
- Indexes
- Relationships to other tables
- Sample data
- Access patterns
- Migration history
```
